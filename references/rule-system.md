# 映射规则总表

三层打分，槽位内排序。每层都给出可追溯的依据，方便复核与二次开发。

## 一、槽位划分

运势倾向不做"全品类混排"——蔬果再吉也当不了主食。

| 槽位 | 品类 |
|---|---|
| 主餐 | 牛肉 BEEF / 鱼 FISH / 鸡肉 CHICKEN / 猪柳 PORK |
| 小食 | 炸物 FRIED / 薯制品 POTATO / 蔬果 VEG |
| 饮品 | 咖啡 COFFEE / 茶饮 TEA / 碳酸饮 SODA |
| 甜品 | 甜品冰品 DESSERT |
| 份额 | 分享餐 SHARE（只影响餐量形式，不参与排序） |

## 二、层 1：宜忌意象 → 品类

权重越高，该品类当日越"当令"。同一条宜可推多个品类。

| 宜 | 推导 | 权重 |
|---|---|---|
| 求嗣 | 鱼（有余、多子）+ 甜品 | +3 / +1 |
| 取渔、结网 | 鱼 | +3 / +2 |
| 纳财、开仓、出货财、置产、立券 | 牛肉（牛市、厚重聚财） | +2 ~ +3 |
| 开市、交易 | 牛肉 + 炸物（热闹） | +2 |
| 动土、破土、起基、竖柱、上梁 | 薯制品（土）+ 牛肉 | +1 ~ +2 |
| 出行、赴任 | 鸡肉（吉）+ 咖啡 | +2 / +1 |
| 嫁娶、会亲友、订盟、纳采 | 分享餐（团聚） | +2 ~ +3 |
| 求医、治病、解除、沐浴、扫舍 | 蔬果 + 茶饮（清淡） | +2 |
| 栽种、牧养 | 蔬果 / 牛肉鸡肉 | +3 / +1 |
| 入学、开光 | 咖啡（清醒）+ 鸡肉 | +2 |
| 祈福、祭祀、斋醮 | 蔬果、甜品、鱼 | +1 ~ +2 |

| 求医 | 蔬果 −3 |
| 入学 | 咖啡 −3 |

## 三、层 2：五行 → 食材

取三个来源投票：**日干五行、日支五行、纳音五行**（如「壬申日 · 剑锋金」= 水 + 金 + 金）。

| 五行 | 麦当劳对应 | 理由 |
|---|---|---|
| 木 | 蔬果、茶饮 | 青、酸、生发 |
| 火 | 炸物、辣味炸鸡 | 赤、苦、焦香 |
| 土 | 牛肉、薯制品、芝士 | 黄、甘、厚实 |
| 金 | 鸡肉（白肉）、麦乐鸡 | 白、辛、清肃 |
| 水 | 鱼、碳酸饮、咖啡 | 黑、咸、流动 |

命中 +1.2；日干五行**所生**的那一行再 +0.6（如壬水生木 → 蔬果、茶饮额外加成）。
五行是同日黄历信息稀少时的主要依据，所以「馀事勿取」这类日子仍能出方案。

## 四、层 3：天气 → 冷热与丰俭

| 体感温度 | 倾向 |
|---|---|
| < 8°C | 牛肉/炸物/薯制品 +2，热饮 +1，冰品 −1.5 |
| 8–15°C | 牛肉/炸物 +1.2，热饮 +0.8 |
| 15–22°C | 中性，冷热皆可 |
| 22–28°C | 蔬果 +0.8、碳酸饮 +0.8，炸物 −0.5 |
| > 28°C | 冰品 +2、碳酸饮 +1.5，炸物 −1.2 |

修正项：

- 有雨（降水量 > 0 或降水概率 ≥ 60%）→ 热食热饮 +1，冰品 −1（外送易化）
- 湿度 > 80% 且 > 22°C → 蔬果 +0.8，炸物 −0.8（湿热不喜油）
- 风速 > 25 km/h → 热饮 +0.8
- 有雨或「忌出行/远行/迁移/赴任」→ **取餐方式默认改外送**

## 五、层 3.5：建除十二神 → 餐量形式

| 值日 | 形式 | 影响 |
|---|---|---|
| 建 / 满 / 成 / 开 | 丰盛 | 分享餐、牛肉、炸物 +1（倾向现成套餐） |
| 定 / 平 / 执 | 均衡 | 无加成 |
| 除 / 收 / 危 | 简约 | 分享餐/炸物 −1，单品 +0.5 |
| 破 / 闭 | 简约 | 分享餐/炸物 −2 |

## 六、指向强度

主餐第一名与第二名的分差：

- ≥ 3 → `high`：黄历指向明确，照办
- ≥ 1 → `medium`：有倾向但不绝对，可按口味微调
- < 1 → `low`：当日宜忌信息稀少，随缘为吉

低强度日**不要硬编理由**，直接说"今天宜忌平淡，按天气和心情挑"。

## 七、菜品归类（`suggest.py`）

按下列**优先级**判定，先中先得。顺序是被真实 SKU 逼出来的，改动前请先跑一遍全量归类核对。

```
0. 周边（丝巾/毛绒/按摩捶/公仔/玩具/礼品/痒痒挠）      → 剔除
1. 多人餐（双人/多人/分享/全家/家庭）                → 剔除（单人场景不适配）
2. 自选型（任选/随心/自选/拼盘）                     → 剔除（内容与价格不可控）
3. 含「堡 / 卷」                                    → 主餐，再按关键词分牛/鱼/鸡/猪
4. 炸物强标志（翅/鸡排/麦乐鸡/四宫格/拼盘/双拼/十翅/芝士条/山葵） → 小食·炸物
5. 薯条薯饼 → 小食·薯；玉米杯苹果片沙拉 → 小食·蔬果
6. 麦旋风/圆筒/新地/冰淇淋/阿芙佳朵/派 → 甜品
7. 咖啡/美式/奶铁/黑巧/浓缩/牛奶/燕麦奶 → 饮品·咖啡
   红茶/锡兰 → 饮品·茶；可乐/雪碧/怡泉/麦炫酷/柠柠/橙橙/苹果汁/纯悦 → 饮品·碳酸
8. 无「堡」但含主餐关键词的套餐（如「"苹"水相"鱼"套餐」） → 对应主餐
9. 其余含「餐 / 套」 → 主餐·牛肉（经典汉堡兜底）
```

主餐关键词优先级：**牛 → 鱼 → 鸡 → 猪**。

```
牛：巨无霸/吉士/安格斯/厚牛/牛堡/双牛/不素之霸/牛肉/牛气/牛
鱼：鳕鱼/麦香鱼/鱼排/鱼
鸡：板/麦辣鸡腿/麦辣鸡/麦香鸡/鸡腿堡/鸡肉堡/脆汁鸡/辣
猪：猪柳/培根
```

关键：**「堡」的判断必须早于其他所有食材词**。否则「培根蔬萃双层牛堡」会被"蔬萃"判成蔬菜、「麦辣鸡腿汉堡」会被拆错。

已踩的坑：

1. **「薄皮V翅双拼十翅」被当成主餐鸡肉** → 因为"鸡翅/V翅"命中了主餐关键词。修法：炸物强标志先判，且它们都不含「堡」。
2. **「堡堡随心拼（7件任选）」被当成天命套餐**（¥72.5，内容自选）→ 修法：自选型直接剔除。
3. **「浓浓黑巧（冰/热）」MCP 默认按冰饮计价**，12°C 天给你冰饮 → 单独提示"需指定热饮"。
4. **牛奶 / 燕麦奶被当成热饮主选** → 排序 −4 降权。
5. **MCP 返回体在 JSON 后同行拼接说明文字**，`json.loads` 整行失败 → 改用 `raw_decode` 容错。

## 八、优惠券规则（`coupons.py`）

### 8.1 三层判定

```
第一层 时间：tradeStartDateTime / tradeEndDateTime → 未生效 / 已过期
第二层 限制：weekdays → tradeTimePeriods → orderTypes → beTypes → currentDayAvailableCount
第三层 事实：calculate-price 带券前后各核一次，差额 > 0 才算数
```

只有三层全过，才允许对用户说「这张券能省 X 元」。

### 8.2 字段陷阱

| 字段 | 坑 |
|---|---|
| `weekdays` | `1=周日 … 7=周六`。Python `weekday()` 是 `0=周一`，直接比会全错。用 `isoweekday() % 7 + 1` |
| `products` | **经常为空数组**。拿不到券对应哪些商品，只能靠标题模糊匹配，必须标注「推测」 |
| `currentDayAvailableCount` | 为 0 表示今天这张券不能核销，哪怕日期在有效期内 |
| `currentChannelCanRedeem` | `false` 时渠道可能核销不了；配合 `toastText: 该券仅限麦当劳App使用` 看 |
| `discountInfo.discountValue` | 固定价券是「用券后价格」，不是优惠金额。别拿去当减免额 |
| `enable` | 与 `currentDayAvailableCount` 不完全同步，别只信这一个 |

### 8.3 券面解析

```
11.9元麦辣鸡腿堡        → fixed_price 11.9, target=麦辣鸡腿堡
19.9元王牌炸鸡任选2     → fixed_price 19.9, target=王牌炸鸡, qty=2
免费脆薯饼              → fixed_price 0
满30减5                → threshold 30 / 5
75折                   → discount 0.75
```

解析不出来的给 `unknown`，**不要猜**。任选 N 件的券要比 N 件原价，且注明"需按实际选品核价"。

### 8.4 商品匹配的排序陷阱

`11.9元麦辣鸡腿堡` 同时像「麦辣鸡腿汉堡」（¥22.5）和「麦辣鸡腿汉堡三件套」（¥33.5）。
按省钱多少排会把三件套顶到第一，看起来省 ¥21.6，实际券根本不作用于套餐。

修法：套餐类名字（`套餐/三件套/四件套/分享餐/双人餐/随心配/拼盘`）相似度 **−0.12** 降权，
展示沿用匹配度排序，不按节省额排序。
